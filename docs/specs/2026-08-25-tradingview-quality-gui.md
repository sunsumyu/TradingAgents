# TradingView 级别 GUI 改造规格文档

> 日期：2026-08-25

## 1. 问题陈述

当前 TradingAgents GUI 虽然已经具备基本的 TradingView 风格布局（左侧工具栏、顶部信息栏、右侧面板、底部指标面板），但与真正的 TradingView 相比存在重大差距：

1. **主 K 线图无法显示数据** — 输入 ticker 后主图区域显示 "暂无 K 线数据"，而 MACD 和 RSI 子面板有数据
2. **绘图工具不可用** — 左侧工具栏按钮存在但点击无效，`DrawingManager.ts` 已实现但未连接到图表
3. **时间周期切换无效** — 1D/1W/1M/3M/1Y/ALL 按钮存在但不触发数据重新加载
4. **Watchlist 点击无响应** — 添加的 ticker 无法点击切换
5. **缺少实时数据流** — 所有数据为静态获取，无 WebSocket 实时推送
6. **缺少多图表布局** — 仅支持单图表，无法分屏对比
7. **指标参数不可配置** — MA/EMA/MACD/RSI/Bollinger 参数硬编码
8. **缺少指标库** — 无 VWAP、Ichimoku、Stochastic、ATR、OBV 等常用指标

## 2. 目标愿景

将 TradingAgents GUI 提升到 **TradingView Lite** 级别的交互体验，同时保持 AI 分析工具的差异化定位。核心目标：

- **流畅的 K 线渲染**：60fps 渲染，平滑滚动和缩放
- **完整的绘图工具链**：趋势线、水平线、矩形、斐波那契、文本标注
- **响应式时间周期切换**：点击即重新加载数据并调整图表
- **可配置的指标系统**：支持添加、移除、配置指标参数
- **实时数据流**：WebSocket 推送实时价格更新
- **多图表布局**：支持 2-4 图表分屏对比

## 4. 实现决策

### 4.1 图表引擎迁移

**决策：从 ECharts 迁移到 lightweight-charts**

- `lightweight-charts` (v5.2) 已安装但未使用，需要将其作为主图表引擎
- ECharts 保留在报告导出（HTML export）和子面板图表中使用
- lightweight-charts 提供：
  - WebGL 加速渲染，60fps 体验
  - 原生 K 线图支持
  - 内置交叉光标同步
  - 更好的大数据集性能
  - TradingView 官方维护

**架构变更：**
- `TradingViewChart.tsx` 重写为 lightweight-charts 渲染器
- `DrawingManager.ts` 接入 lightweight-charts 的 `IPanePrimitive` 接口
- 子面板（MACD/RSI/Bollinger）继续使用 ECharts（通过自定义 primitive 连接到 lightweight-charts）

### 4.2 绘图工具架构

**决策：基于 lightweight-charts IPanePrimitive 实现**

- `DrawingManager.ts` 已有完整实现（416 行），需要：
  1. 修复类型兼容性问题
  2. 接入 TradingViewChart 组件
  3. 添加持久化（localStorage）
  4. 添加新的绘图类型（文本标注、平行通道）
  5. 添加撤销/重做功能

**绘图工具状态管理：**
- 使用 React Context 管理当前选中的绘图工具
- 绘图数据存储在组件 state 中
- 绘图操作通过 Command 模式支持撤销/重做

### 4.3 时间周期系统

**决策：统一时间周期管理**

- 创建 `TimeframeManager` 统一管理时间周期状态
- 时间周期切换触发数据重新加载（调用 `/api/chart-data`）
- 后端需要支持不同时间粒度的 OHLCV 数据聚合
- 前端缓存已加载的时间周期数据

**时间周期映射：**
```
1D  -> daily data (default)
1W  -> weekly aggregation
1M  -> monthly aggregation
3M  -> 3-month view (daily data, wider range)
1Y  -> 1-year view (daily data, wider range)
ALL -> all available data
```

### 4.4 指标系统

**决策：插件化指标架构**

- 创建 `IndicatorRegistry` 注册中心
- 每个指标实现 `IndicatorPlugin` 接口：
  ```typescript
  interface IndicatorPlugin {
    id: string;
    name: string;
    nameZh: string;
    category: 'overlay' | 'oscillator' | 'volume';
    defaultParams: Record<string, number>;
    paramSchema: ParamSchema[];
    calculate(data: CandleData[], params: Record<string, number>): IndicatorResult;
    render(chart: IChartApi, data: IndicatorResult): ISeriesPrimitive;
  }
  ```
- 指标 UI 通过 schema 自动生成配置表单
- 支持自定义指标（用户编写计算公式）

**初始指标集：**
- Overlay: MA, EMA, Bollinger, VWAP, Ichimoku
- Oscillator: MACD, RSI, Stochastic, CCI, Williams%R, ADX
- Volume: OBV, Volume Profile

### 4.5 实时数据流

**决策：WebSocket + SSE 混合架构**

- 实时价格数据通过 WebSocket 推送（低延迟）
- AI 分析进度通过 SSE 推送（已有实现）
- 后端需要实现 WebSocket 服务器（使用 FastAPI WebSocket）
- 前端实现重连逻辑（指数退避）

**WebSocket 消息格式：**
```json
{
  "type": "price_update",
  "ticker": "600733",
  "price": 12.50,
  "change": 0.25,
  "changePercent": 2.04,
  "volume": 1234567,
  "timestamp": "2026-08-25T00:00:00Z"
}
```

### 4.6 Watchlist 架构

**决策：本地存储 + 可选云端同步**

- Watchlist 数据存储在 localStorage
- 支持导入/导出 JSON 文件
- 可选：通过 API 同步到服务器（需要用户登录）
- Watchlist 组件支持拖拽排序（使用 dnd-kit）

### 4.7 多图表布局

**决策：CSS Grid 布局 + 独立图表实例**

- 使用 CSS Grid 实现灵活的图表布局
- 每个图表面板是独立的 lightweight-charts 实例
- 十字光标同步通过自定义 primitive 实现
- 布局状态保存在 localStorage

### 4.8 报告图表

**决策：保持 ECharts 用于报告导出**

- 报告中的图表继续使用 ECharts（兼容性好）
- 支持将 ECharts 图表导出为静态图片嵌入 HTML/PDF
- 报告中的图表保持只读（不支持交互操作）

### 4.9 性能优化策略

**决策：渐进式加载 + 虚拟滚动**

- 大数据集使用渐进式加载（先加载最近数据，滚动时加载历史）
- K 线图使用 lightweight-charts 的内置虚拟化
- 指标计算使用 Web Worker（避免阻塞主线程）
- 图片资源使用懒加载

## 6. 范围外

以下功能不在本次改造范围内：

1. **实盘交易** — 本工具定位为 AI 分析，不涉及交易执行
2. **移动端适配** — 仅支持桌面端（Tauri 应用）
3. **多账户管理** — 不支持多用户/多账户
4. **自定义主题商店** — 仅支持内置主题
5. **社交功能** — 不支持分享、评论、关注
6. **回测功能** — 策略回测为独立功能模块
7. **告警系统** — 价格/指标告警为后续迭代
