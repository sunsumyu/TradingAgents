## 1. 开发方法论

### 1.1 文档驱动开发 (DDD) 原则

1. **文档先行** — 在编写任何代码之前，先完成规格文档
2. **单一事实来源** — 规格文档是唯一的实现依据
3. **可追溯性** — 每个代码变更都能追溯到规格文档的特定条目
4. **评审驱动** — 规格文档需要经过评审才能开始实现
5. **增量交付** — 按规格文档的阶段划分增量交付

### 1.2 工作流程

```
需求收集
    ↓
规格文档编写（使用 to-spec skill）
    ↓
规格评审（用户确认）
    ↓
任务分解（使用 to-tickets skill）
    ↓
实施计划制定（使用 writing-plans skill）
    ↓
代码实现
    ↓
验证完成（使用 verification-before-completion skill）
```

## 4. 规格文档模板

### 4.1 标准规格文档结构

```markdown
# [功能名称] 规格文档

> 日期：YYYY-MM-DD
> 状态：Draft | In Review | Approved | Implemented
> 优先级：P0 | P1 | P2 | P3
> 关联：[相关文档链接]

---

## 1. 问题描述
[描述当前问题或需求]

## 2. 目标
[描述要达成的目标]

## 3. 用户故事
[列出用户故事]

## 4. 实现决策
[列出技术决策]

## 5. 测试决策
[列出测试策略]

## 6. 范围外
[列出不在范围内的功能]

## 7. 验收标准
[列出验收标准]

## 8. 时间估算
[估算时间]

## 9. 风险与缓解
[列出风险和缓解措施]
```

```

```
